## MANDATORY — BACKUP AND VERIFY PROTOCOL — BEFORE EVERY WRITE

**Every write to `index.html`, `css/styles.css`, `js/app.js`, `js/api.js`, or `data/tasks.json` requires all steps below, in order. No exceptions — not for single-line edits, not for bug fixes, not for anything.**

### Before making any change
1. Identify the exact file(s) you will change.
2. GET the current live file via GitHub Contents API.
3. Confirm the file size is non-zero before proceeding — if zero or unexpectedly small, stop and tell Kevin.
4. Create a timestamped backup in `Archive/`: `index_backup_YYYYMMDD_HHMM.html` or `tasks_backup_YYYYMMDD_HHMM.json`.
5. Commit the backup immediately — before any edit.
6. GET the backup back from GitHub and confirm the returned SHA matches the committed file.
7. Only then make the requested change.

### After making any change
8. Read the changed file back and confirm the git SHA.
9. If anything is wrong, restore from the verified backup before continuing.

### Rules
- Backup before write — every change, no exceptions.
- Verify file size before backup — never back up an empty or stub file.
- Verify backup SHA before modifying.
- Verify post-change SHA after writing.
- Do not proceed on assumptions.
- Do not skip verification steps.
- One change at a time — do not bundle unrelated changes.
- Do not advance to the next stage until the current stage is verified and clean.

## Data Flow
Tasks load from `data/tasks.json` on page open (cache-busted). The 'From your inbox' panel loads AI task suggestions from work-inbox `data/inbox_suggestions.json` (generated by fetch_inbox.py Phase 3.5, six times daily); drag a suggestion card into a tier list to add it as a real task; dismissals persist in localStorage. Updates to existing tasks are auto-applied by fetch_inbox.py Phase 3.6 as dated action entries (deduped via work-inbox data/triage_ledger.json, daily Archive/ backup enforced before every write). Done-state persists in `localStorage` (key: `commandCentre_done_v1`). Quick-add tasks, tier moves (buttons or drag-and-drop), notes edits and suggestion drags persist to tasks.json via the Cloudflare Worker `cc-tasks-writer.kevinlelitte.workers.dev` (Kevin's Cloudflare account). The Worker holds a fine-grained GitHub PAT (Contents RW, command-centre + work-inbox only) as a server-side secret, only writes data/tasks.json, enforces the daily Archive/ backup, and is CORS-locked to the dashboard origin. Nothing is stored on any client machine — any browser works.

## Task Data Standard (established 08 Jun 2026)
Each task in data/tasks.json follows this structure:
- **description** — the issue, background, context, history, dependencies. What it is and why it matters.
- **actions** — a dated log of everything done and everything still to do. Format: [DD Mon YYYY] for completed. [TODO] for pending. [AWAITING] for blocked on someone else. [MONITOR] for passive watch items.
- **entryId** — Outlook EntryID of the most recent linked email. Set automatically by inbox triage and suggestion drag; powers the Open email button.
- Never put actions in description. Never put context or history in actions.
- Rollback: Archive/tasks_backup_20260608.json contains pre-standard snapshot.

## Rollback procedure

If a bad push is made, restore as follows:

Step 1 — Find the last good commit:
GET https://api.github.com/repos/begb0037admin/command-centre/commits?path=data/tasks.json&per_page=5
Identify the commit SHA immediately before the bad one.

Step 2 — Fetch the file at that commit:
GET https://api.github.com/repos/begb0037admin/command-centre/contents/data/tasks.json?ref=COMMIT_SHA
Decode the base64 content field.

Step 3 — Restore via PUT with the old content and message 'Rollback to COMMIT_SHA'.

Alternative — restore from Archive/: fetch tasks_backup_YYYYMMDD.json for the nearest date
and PUT it back. For index.html use index_backup_YYYYMMDD.html.
